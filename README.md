# Brigade-Ops — სამუშაოს ანგარიშის გენერატორი

## ფაილები

```
app.py              Flask სერვერი (API, Excel, ადმინ API)
config.json         საწყისი ბრიგადები და სამუშაოს ტიპები (მხოლოდ პირველი გაშვებისთვის)
logo.png            ლოგო / favicon
requirements.txt
vercel.json
overtime.py         Overtime მოდული (Blueprint, ცალკე სქემა overtime.*)
templates/
  index.html        მთავარი გვერდი — ანგარიშები
  admin.html        ადმინ პანელი — /admin
  overtime.html     Overtime — /overtime
```

## Vercel-ზე ატვირთვა

1. ჩაანაცვლეთ ყველა ფაილი ამ ფოლდერის ფაილებით (`templates/` ფოლდერის ჩათვლით).
2. Vercel → Project → **Settings → Environment Variables** დაამატეთ:
   - `ADMIN_PASSWORD` — ადმინ პანელის პაროლი (სავალდებულო, მის გარეშე ადმინ პანელი გამორთულია)
   - `POSTGRES_URL` — უკვე გაქვთ დაყენებული
3. გააკეთეთ Redeploy.

## როგორ ინახება ბრიგადები

Vercel-ზე ფაილში ჩაწერა შეუძლებელია, ამიტომ ბრიგადები და სამუშაოს ტიპები ახლა ინახება
მონაცემთა ბაზის `settings` ცხრილში (იქმნება ავტომატურად).

- პირველ გაშვებაზე მონაცემები ავტომატურად გადაიტანება `config.json`-იდან.
- ამის შემდეგ ყველა ცვლილება კეთდება ადმინ პანელიდან (`/admin`).
- `config.json`-ის შეცვლა აღარ მოქმედებს, სანამ ადმინ პანელში არ დააჭერთ
  „config.json-ის საწყის მდგომარეობაზე დაბრუნება“-ს.
- ადმინ პანელში შეგიძლიათ ჩამოტვირთოთ მიმდინარე პარამეტრები `config.json` ფაილად (backup).

## Excel-ის ფილტრი

„📍 ლოკაცია“: ყველა / თბილისი / რეგიონი. „რეგიონი“-ს არჩევისას ჩნდება მეორე სია
რეგიონის ქალაქებით (ყველა ქალაქი, გარდა თბილისისა). Excel-ში გადის ზუსტად ის ჩანაწერები,
რაც ცხრილში ჩანს ფილტრის შემდეგ.

## v3 — აღრიცხვის (Book2.xlsx) ფორმატი

**Excel** — 3 ფურცელი:
- **აღრიცხვა** — სვეტები A–Y ზუსტად ემთხვევა „აღრიცხვა 2026“ ფაილს (შეგიძლიათ პირდაპირ ჩააკოპიროთ).
  Z–AB დამატებითია: ქალაქი, კოეფიციენტი, სხვა ბრიგადიდან.
- **შეჯამება** — თითოეულ თანამშრომელზე: დღეები, გაცდენები, საათები, თანხები.
- **ტარიფები** — მიმდინარე ტარიფები.

**გამოთვლები** (Book2.xlsx-ის მიხედვით):
- რაოდ. კაცი = რაოდენობა ჯამი ÷ ბრიგ. წევრ. რაოდ. (ბრიგადირს / უფროსს — 1)
- თანხა = ტარიფი × რაოდ. კაცი (მუშა, ბრიგადა, ინჟინერი)
- რაოდენობა საათი = დასრულება − დაწყება (ღამის სამუშაო შუაღამის გადაკვეთით, მაგ. 21:30→05:00 = 7:30)
- გაცდენა: ერთი სტრიქონი დღეში, „@“ ველებით, 9:00–18:00, მიზეზი „კომენტარი“-ში
- ზოგადი კომენტარი (საბონუსე, დღიური ანაზღაურება, ღამის სამუშაო) Excel-ის „კომენტარი“ სვეტში გადის

**ტარიფი ფიქსირდება შენახვისას** — ადმინ პანელში ტარიფის შეცვლა ძველ ჩანაწერებზე არ მოქმედებს.

**ავტომატური განახლება**: პირველ გაშვებაზე ბაზის არსებული პარამეტრები ავტომატურად გადადის ახალ ფორმატზე —
ბრიგადები და წევრები რჩება, ემატება ტარიფები, ავტომობილები და ინჟინრები.

### 1. სამუშაო დროის თანხვედრა
- შენახვისას (ახალიც და რედაქტირებაც) სერვერი ამოწმებს თითოეული **მომუშავე** წევრის სამუშაო დროს
  ყველა სხვა ჩანაწერთან იმავე თარიღში (± 1 დღე — ღამის ცვლისთვის), ნებისმიერ ბრიგადაში, მიუხედავად
  იმისა, როდის შეიქმნა ან რედაქტირდა.
- ამოწმებს ნაწილობრივ თანხვედრასაც (10:00–17:00 vs 16:00–18:00). მხოლოდ შეხება (17:00–18:00) თანხვედრა არ არის.
- შედარება: პირადი ნომერი (თუ არ აქვს — სახელი), თარიღი, საათები. გაცდენაზე მყოფი და დროის გარეშე სამუშაოები არ მოწმდება.
- ფანჯარა: „გაუქმება“ (ბრუნდება რედაქტირებაზე) ან „მაინც შენახვა“ — დადასტურება ჟურნალში ფიქსირდება.

### 2. ოპერატორები და აქტივობის ჟურნალი
- ადმინ პანელი → **🔑 ოპერატორები**: ანგარიშის დამატება, სახელის/პაროლის შეცვლა, დაბლოკვა, წაშლა.
  სანამ აქტიური ოპერატორი არ არსებობს, მთავარი გვერდი ღიაა (მოქმედებები IP-ით აღირიცხება).
  პირველი ოპერატორის დამატებისთანავე შესვლა სავალდებულო ხდება.
- პაროლის შეცვლა/დაბლოკვა ძველ სესიებს აუქმებს. 15 წუთში ერთი IP-დან 8 წარუმატებელი შესვლის შემდეგ — დაბლოკვა 15 წუთით.
- ადმინ პანელი → **📜 აქტივობა**: დრო, მომხმარებელი, IP, მოქმედება, ID, ცვლილების აღწერა.
  ფილტრები: მომხმარებელი, IP, პერიოდი, მოქმედების ტიპი, ID. ცხრილში მომხმარებელზე/IP-ზე/ID-ზე დაჭერა ფილტრავს.
- IP სერვერზე ფიქსირდება: Vercel-ზე `X-Vercel-Forwarded-For` / `X-Forwarded-For` (Vercel თავად წერს — გაყალბება შეუძლებელია),
  სხვაგან — პირდაპირი კავშირის მისამართი (პროქსის უკან `TRUST_PROXY=1`).
- ჟურნალი (`activity_log` ცხრილი) მხოლოდ ემატება: ცვლილება/წაშლის API არ არსებობს და Postgres-ის ტრიგერი UPDATE/DELETE-ს ბლოკავს.

რეკომენდებული: Vercel-ში დაამატეთ `SECRET_KEY` (ნებისმიერი გრძელი შემთხვევითი ტექსტი) — სესიის ქუქის ხელმოწერისთვის.
თუ არ არის, გამოიყენება ADMIN_PASSWORD-იდან მიღებული გასაღები (ADMIN_PASSWORD-ის შეცვლა ყველა ოპერატორს გამოიყვანს სისტემიდან).

## v4.1 — დღის კომენტარები

„შენახული ჩანაწერები“ → ტაბი **„💬 დღის კომენტარები“**:
- ერთი სტრიქონი = **ერთი რეგიონის ერთი ბრიგადის ერთი დღე** (ქალაქი + ბრიგადა + თარიღი) და ამ დღის ყველა ჩანაწერი (ID).
- ფილტრი: რეგიონი, ბრიგადა, დღე/პერიოდი („დღეს“, „გუშინ“, „ეს თვე“), ჩვენება: კომენტარით / გარეშე / განსხვავებული.
- კომენტარის ჩაწერა სტრიქონში → „შენახვა“ (ან Enter); ან რამდენიმე დღის მონიშვნა → „მონიშნულებზე კომენტარი“. ცარიელი = წაშლა.
- ინახება ბაზაში — ამ დღის თითოეული ჩანაწერის „ზოგადი კომენტარი“ ველში; Excel-ის „კომენტარი“ სვეტში აისახება მხოლოდ ამ ჩანაწერების
  ნამუშევარ სტრიქონებზე (გაცდენის სტრიქონებში მიზეზი რჩება). სხვა ბრიგადა, სხვა რეგიონი ან სხვა დღე არ იცვლება.
- ბოლო რედაქტირება იმარჯვებს: ჩანაწერის ფორმიდან ან ამ ტაბიდან — რომელიც ბოლოს შეინახა.
